# PLAN

## Активная задача
Синхронизировать текущую ветку `various_fixes` с `upstream/master`, разрешить все merge-конфликты и оставить ветку в согласованном состоянии без незавершенного merge/rebase.

## Scope
- Проверить текущее git-состояние и расхождение с `upstream/master`.
- Обновить refs из `upstream`.
- Вмержить `upstream/master` в `various_fixes`.
- Разрешить конфликты только в объеме, необходимом для корректного sync.
- Проверить итоговый git-state, conflict markers и релевантные последствия для сборки.

## Out of scope
- Переписывание истории через rebase.
- Несвязанные рефакторинги и cleanup вне зон конфликтов.
- Новые фичи, не требуемые для merge-resolution.

## Challenge block
### Сомнения
1. Локальный `upstream/master` может отставать от удаленного `upstream/master`.
2. Ветка уже содержит merge-коммиты с `master`, поэтому rebase может сломать историю и сильно увеличить риск регрессий.
3. Конфликты могут затронуть `AI_AGENT` task-state и другие служебные файлы вместе с DM/map-кодом.

### Альтернативы
1. Merge `upstream/master` в текущую ветку.
2. Rebase `various_fixes` на `upstream/master`.

### Выбор
- Выбран merge: история ветки уже merge-oriented, расхождение большое (`383` локальных коммита), а пользователь просит именно обновить ветку до `upstream/master` и решить конфликты.

### Почему не rebase
- Слишком высокий риск переписать историю и получить каскад конфликтов на сотнях коммитов.
- Не соответствует уже используемому паттерну этой ветки (`Merge branch 'master' into various_fixes` присутствует в истории).

## Фазы
1. Собрать факты по refs, дивергенции и отсутствию незавершенного merge/rebase.
2. Обновить `upstream/master` через `git fetch`.
3. Выполнить merge и разрешить конфликты.
4. Проверить итоговый state, diff и релевантные проверки.

## Текущий статус
- Merge подготовлен в индексе.
- Конфликты разрешены.
- Идет финализация merge-коммита и контрольный git-state.

## Acceptance criteria
- `git fetch upstream master` выполнен успешно или явно зафиксирован как блокер.
- `upstream/master` является предком `HEAD` после sync.
- В рабочем дереве нет merge-conflict markers и незавершенного merge/rebase.
- Выполнены как минимум `git status`, `git diff --check` и точечные проверки по затронутым зонам; если сборка не запускалась, причина указана явно.

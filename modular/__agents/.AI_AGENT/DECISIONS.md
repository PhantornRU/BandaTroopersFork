# DECISIONS

## D-001: Синхронизация делается через merge, а не через rebase
- Решение: влить `upstream/master` в `various_fixes`.
- Почему: ветка уже живет с merge-историей, расхождение велико, а rebase на `383` локальных коммита слишком рискован для этой задачи.

## D-002: Сначала fetch, потом merge
- Решение: не полагаться на локальный ref `upstream/master`, а сначала обновить его через `git fetch upstream master`.
- Почему: пользователь просит синхронизацию именно с `upstream/master`, значит нужен актуальный remote state, а не потенциально устаревший локальный ref.

## D-003: Конфликты решаются минимально-инвазивно
- Решение: сохранять логику ветки `various_fixes`, если апстрим не приносит обязательный фикс, и не делать несвязанный cleanup.
- Почему: цель задачи в корректном sync, а не в рефакторинге и не в переписывании существующей логики ветки.

## D-004: Отсутствующий `HALO_PORT_STATE.md` не блокирует sync
- Решение: продолжать работу без этого документа, так как файл не найден в рабочем дереве.
- Почему: инструкция на него ссылается, но репозиторий не содержит файл по ожидаемому имени; блокировать merge из-за отсутствующей документации нельзя.

# RTO Support: геймдизайн

## 1. Цель роли

`RTO Support` делает RTO отдельной support-ролью с читаемым циклом:

1. выбрать пакет;
2. занять позицию;
3. развернуть сектор;
4. вызывать поддержку внутри сектора;
5. управлять shared и personal cooldown.

Это лучше, чем старый разрозненный designator-flow, потому что у роли появляется явная специализация и тактическая фаза подготовки.

Точные численные параметры пакетов и текущие значения кулдаунов вынесены в [RTO_SUPPORT_BALANCE.md](RTO_SUPPORT_BALANCE.md). Этот документ остаётся про роль, назначение пакетов и продуктовые ограничения.

## 2. Базовые правила

- Один пресет на жизнь моба.
- Один активный сектор на оператора.
- Поддержка вызывается только через RTO-бинокль.
- Большинство способностей требуют активный сектор.
- Сектор не скрывает ограничения карты: LOS, потолки и корабельные уровни всё равно валидируются.

## 3. Почему сектор обязателен

`Сектор наведения` нужен не ради технической сложности, а ради структуры роли.

Он:

- отделяет наблюдение от удара;
- заставляет RTO заранее выбрать область работы;
- даёт команде контригру через позицию и время;
- позволяет балансировать пакеты через радиус, длительность и кулдаун сектора.

Если убрать сектор, роль быстро деградирует в набор instant-click кнопок.

## 4. Стартовые пресеты

## Mortar

Роль пакета:

- площадной контроль;
- дым;
- зажигательное давление;
- высокий разброс и хороший темп вызовов.

Параметры:

- радиус сектора: `7`
- длительность сектора: `90 секунд`
- кулдаун сектора: `45 секунд`

Способности:

- `HE mortar`: scatter `6`, shared `12`, personal `45`
- `Smoke mortar`: scatter `5`, shared `10`, personal `35`
- `Incendiary mortar`: scatter `6`, shared `15`, personal `60`

Особенность:

- при развертывании сектора используется illumination payload с фальшфейером.

## CAS

Роль пакета:

- точечный быстрый удар;
- сопровождение штурма;
- высокая зависимость от открытого неба.

Параметры:

- радиус сектора: `5`
- длительность сектора: `90 секунд`
- кулдаун сектора: `60 секунд`

Способности:

- `Gun run`: scatter `3`, shared `18`, personal `70`
- `Laser run`: scatter `2`, shared `20`, personal `80`
- `Rocket barrage`: scatter `4`, shared `20`, personal `90`

Особенность:

- сектор и способности пакета требуют high-altitude validation.

## Heavy Strike

Роль пакета:

- редкий тяжёлый удар;
- высокая цена ошибки;
- меньший темп, но сильный пик силы.

Параметры:

- радиус сектора: `4`
- длительность сектора: `90 секунд`
- кулдаун сектора: `70 секунд`

Способности:

- `Missile strike`: scatter `2`, shared `25`, personal `90`
- `Napalm strike`: scatter `3`, shared `25`, personal `110`

## Logistics

Роль пакета:

- utility support;
- выгрузка припасов и турелей;
- меньше прямой летальности, больше позиционной пользы.

Параметры:

- радиус сектора: `6`
- длительность сектора: `90 секунд`
- кулдаун сектора: `50 секунд`

Способности:

- `Supply drop`: scatter `1`, shared `20`, personal `90`
- `Sentry drop`: scatter `1`, shared `20`, personal `120`

Особенность:

- выгрузка запрещена в закрытые тайлы.

## 5. Балансные принципы

### Shared cooldown

Нужен, чтобы:

- RTO не спамил всеми кнопками подряд;
- выбор способности в моменте имел цену;
- пакеты читались как набор ролей, а не как all-in-one toolbox.

### Personal cooldown

Нужен, чтобы:

- одна и та же сильная способность не повторялась без паузы;
- внутри пакета сохранялась ротация между кнопками;
- редкие heavy/logistics вызовы оставались ценными.

### Разброс

Scatter сейчас intentionally разный:

- mortar прощает точность, но даёт зону;
- CAS бьёт точнее;
- heavy страдает меньше всего, но стреляет реже;
- logistics почти не должен промахиваться.

## 6. Осознанные ограничения

- Единая базовая длительность сектора в `90 секунд`.
- Нет свободной смены пакета посреди жизни.
- Нет вызовов вне сектора даже для “быстрых” пакетов.

Это решение спорное, но на текущем этапе оправдано читаемостью и балансом.

## 7. Что вероятнее всего тюнить дальше

- shared cooldown у CAS;
- personal cooldown у heavy strike;
- utility-ценность logistics;
- радиус сектора mortar;
- длительность сектора по пакетам, если единое значение окажется слишком щедрым.

## 8. Rejected alternatives

### Свободная смена пресета в течение раунда

Отклонено, потому что:

- ломает специализацию роли;
- резко усложняет баланс;
- делает интерфейс и runtime более хрупкими.

### Вызов поддержки без сектора

Отклонено, потому что:

- убирает фазу подготовки;
- ускоряет роль до instant-click паттерна;
- делает пакеты слишком похожими друг на друга.

# World Edit Visual Workbench

World Edit Visual Workbench is the user-facing visual acceptance harness for `building_layout`. It is intended for development and review of generated buildings, not for live game UX.

The workbench is intentionally file-based:

```text
data/world_edit_visual/enabled.txt
data/world_edit_visual/inbox/*.json
data/world_edit_visual/out/<case_id>/report.json
data/world_edit_visual/out/<case_id>/semantic.json
```

`tools/world_edit_visual` contains helper scripts and sample cases. The canonical runtime state is repo-root `data/world_edit_visual`.

## What It Tests

The workbench exercises the real `building_layout` generator path:

```text
case JSON
  -> bounded visual canvas
  -> World Edit shape contract
  -> building_layout support report
  -> build_plan_from_shape_contract()
  -> apply_plan()
  -> post_emit_validation metadata
  -> report.json and semantic.json
```

This means a supported case is generated by the same DM generator path used by World Edit. It is not a Python-side generator, fake fixture placer, or side implementation.

Unsupported shapes stay unsupported. A locked shape writes a locked report and does not mutate the canvas.

## Setup And Run

From the repository root:

```powershell
py -3 tools/world_edit_visual/prepare_cases.py tools/world_edit_visual/cases
```

`prepare_cases.py` creates the canonical runtime directories, the enabled flag, and per-case output folders before copying case JSON files into the inbox.

Start the DM runtime after the flag exists. The workbench starts only when this file is present before world initialization:

```text
data/world_edit_visual/enabled.txt
```

Copy one case:

```powershell
tools\world_edit_visual\run_case.bat tools\world_edit_visual\cases\building_living_rectangle_colony.json
```

Copy all sample cases:

```powershell
tools\world_edit_visual\run_all.bat
```

Render outputs:

```powershell
py -3 tools/world_edit_visual/render_semantic.py --semantic-json data/world_edit_visual/out/building_living_rectangle_colony/semantic.json --report-json data/world_edit_visual/out/building_living_rectangle_colony/report.json --out data/world_edit_visual/out/building_living_rectangle_colony/semantic.png
```

Or watch for outputs:

```powershell
py -3 tools/world_edit_visual/watch_cases.py
```

Build the index:

```powershell
py -3 tools/world_edit_visual/build_index.py
```

`build_index.py` writes `tools/world_edit_visual/index.md`.

## Case Schema

Current cases target `building_layout` only.

```json
{
  "id": "building_living_rectangle_colony",
  "generator": "building_layout",
  "seed": 1001,
  "canvas": {
    "preset": "blank_96",
    "width": 96,
    "height": 96
  },
  "shape": {
    "id": "rectangle",
    "anchors": [
      { "x": 20, "y": 20 },
      { "x": 43, "y": 39 }
    ]
  },
  "config": {
    "program": "living",
    "faction_preset": "colony",
    "direction": "east",
    "respect_blockers": false,
    "replace_blocked_turfs": true
  },
  "expect": {
    "status": "supported"
  },
  "render": {
    "semantic_png": true,
    "after_dmm": false,
    "debug_overlays": true
  },
  "profile": {
    "enabled": true
  }
}
```

Fields:

- `id`: required case id and output directory name after sanitization.
- `generator`: required; must be `building_layout`.
- `seed`: optional deterministic seed. It is mapped to `building_seed` unless already supplied in `config`.
- `canvas`: `preset`, `width`, `height`; size is clamped to the MVP canvas limits.
- `shape`: World Edit shape id plus local canvas anchors.
- `config`: real `building_layout` params. `program` is mapped to `archetype_id` when needed.
- `expect`: expectations for reviewers or future automation.
- `render`: requested artifacts. `after_dmm` is warning-only.
- `profile`: enables DM stage profiling.

Sample case intent:

- `building_line_locked.json`: expected locked line-shape case.
- `building_living_rectangle_colony.json`: explicit rectangle diagnostic case. Current production `building_layout` can fail it at preview validation with `sleep_privacy` route/connectivity errors; this is tracked as `E-WEV-001` in `modular/__agents/.AI_AGENT/CONFIRMED_UNRESOLVED_ERRORS.md`.
- `building_living_point_colony.json`: point smoke case for production generation. Current production `building_layout` can fail it at preview validation with `sanitation` connectivity errors; this is tracked as `E-WEV-002`.

The Workbench intentionally reports these generator failures instead of hiding them with a visualizer fallback.

## Report Output

`report.json` schema:

```text
world_edit_visual_report/v1
```

Important fields:

- `case_id`, `generator`, `seed`, `program`, `shape`, `style`.
- `status`: `supported`, `locked`, or `error`.
- `stage`: current final stage or failing stage.
- `errors`: structured diagnostics with `code`, `message`, `severity`, `stage`, and optional coordinates/details.
- `warnings`: warning strings.
- `metrics`: generated turf/object counts, changed turf counts, validation counts, and semantic/building counters when available.
- `rooms`, `routes`, `direction`: selected building metadata from the plan.
- `profile`: DM stage timings and counters.
- `artifacts`: expected artifact names.

Common stages:

- `load_case`
- `canvas_setup`
- `support_check`
- `preview`
- `apply`
- `post_emit_validation`
- `export`

## Semantic Output

`semantic.json` schema:

```text
world_edit_visual_semantic/v1
```

Important fields:

- `case_id`, `width`, `height`, `origin`.
- `tiles`: canvas tiles with absolute `x/y`, local `local_x/local_y`, turf path, area path, density, opacity, flags, and objects.
- `flags`: `floor`, `wall`, `door`, `reserved_walk`, `blocked`, `changed`, and `error`.
- `objects`: emitted object path, density, direction, slot/provider metadata, and functional flag when metadata exists.
- `rooms`: room reports from generator metadata.
- `routes`: route/corridor metadata from generator metadata.
- `markers`: anchors and center markers.
- `errors`: copied structured errors.
- `profile`: optional copied profile data.

The renderer turns this semantic data into a schematic PNG. It does not inspect DMI icon states and should be read as a visual debugging map, not final sprite output.


Watch all outputs:

```powershell
py -3 tools/world_edit_visual/watch_cases.py
```

Build the index:

```powershell

```

## MVP Limitations

- The preferred visual canvas is a compiled static canvas map at `modular/world_edit/maps/world_edit_visual_canvas.dmm`. Runtime dynamic z allocation remains fallback-only and is not the acceptance path.
- The canvas clears only the bounded region requested by the case.
- `after.dmm` is not available in this MVP. If requested, it produces a warning and `semantic.json` remains the source of truth.
- `semantic.png` is a schematic renderer output, not a sprite-perfect map preview.
- The real generation path is `building_layout`; locked shapes are not converted to alternate supported geometry.
- DM profiling is decisecond-granularity. Fast stages can appear as `0 ds`.

## Troubleshooting

No report is written:

- Create `data/world_edit_visual/enabled.txt` before starting the runtime.
- Ensure the runtime is still running and the case is under `data/world_edit_visual/inbox`.
- Ensure the case file is valid JSON and has an `id`.

Case is ignored:

- The workbench only processes `.json` files.
- A file is processed by filename and content hash. Change the file content or use a new filename/case id for repeat tests.

Case errors during load:

- Check `report.json` for `invalid_json_case`, `missing_case_id`, or `unsupported_visual_generator`.
- Use `generator: "building_layout"`.

Case locks at support check:

- Inspect `reason_code`. This is expected for unsupported shapes such as `line`.

Renderer fails:

- Install Pillow with `py -3 -m pip install Pillow`.
- Pass the repo-root `data/world_edit_visual/out/<case_id>/semantic.json` path.

`after.dmm` is absent:

- Expected for the MVP. Use `semantic.json`, `report.json`, and `semantic.png`.

Wrong runtime path:

- Use `data/world_edit_visual/...` from repo root. Do not use `tools/world_edit_visual/data/...` as the runtime inbox, output directory, or enabled flag.

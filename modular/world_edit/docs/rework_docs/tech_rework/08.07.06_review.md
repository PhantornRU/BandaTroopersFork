# Детальный план реализации v2.1: универсальная генерация через Pattern → Room Allocation → Opening Solver → Scene Hierarchy

Текущие правки идут в правильную сторону, но пока не решают универсальную генерацию. Сейчас `v2` включается только при `use_layout_v2` и только для `living`, то есть архитектурно это ещё не общий генератор для всех программ.
Также текущий `living` использует только два layout pattern: `front_common_back_private` и `central_spine_rooms`.  Внутри этих паттернов двери всё ещё ставятся координатами через `add_building_v2_door(...)`, например `spine_x`, `left_door_x`, `right_door_x`.

Главная цель v2.1:

```text
Паттерн больше не строит финальную карту.
Паттерн задаёт отношения и зоны.
Solver строит комнаты, двери, окна и сцены по правилам.
```

---

# 0. Целевой pipeline

Новый порядок:

```text
Program Contract
→ Layout Pattern: influence zones + required connections
→ Room Allocation Solver
→ Route Solver
→ Opening Solver: doors/windows
→ Scene Solver: primary/secondary/detail/negative space
→ Placement Module Solver
→ Quality Validator
→ Emit to existing state
```

Текущий `Scene Solver` уже существует, но он пока работает как `switch(scene_contract.id)` и напрямую строит отдельные сцены: `common_dining_4`, `bedroom_bed_cabinet`, `sanitation_toilet_sink`, `storage_rack_wall` и т.д.  Это нужно оставить как базу, но перестроить вокруг `scene hierarchy`.

# ЭТАП 1. Изоляция hardcode и Opening Solver

## 1.1. Проблема

Сейчас паттерн вручную вызывает:

```dm
add_building_v2_door(context, candidate, "front_entry", "main_exit", spine_x, 1, NORTH, "", "route")
add_building_v2_door(context, candidate, "common_to_spine", "door", left_door_x, ..., WEST, "entry_common", "route")
```

Пример этого есть в текущем `central_spine_rooms`.

Это неправильно для универсальной генерации, потому что:

```text
дверь задаётся формулой;
дверь не выбирается из shared wall;
дверь не знает segment length;
дверь не знает соседние двери;
дверь не знает privacy transition;
дверь не знает реальный passability graph.
```

## 1.2. Что меняем

Паттерн больше не вызывает `add_building_v2_door()`.

Вместо этого он добавляет связи:

```dm
add_building_v2_connection(candidate, "entry_common", "route", "public")
add_building_v2_connection(candidate, "sleeping", "route", "private")
add_building_v2_connection(candidate, "sanitation", "route", "private")
add_building_v2_connection(candidate, "storage", "route", "service")
```

## 1.5. Opening Solver

Новый файл:

```text
modular/world_edit/code/generators/building_layout/v2/building_layout_v2_opening_solver.dm
```

### Entry point

```dm
/datum/world_edit_generator/building_layout/proc/solve_building_v2_openings(
	datum/world_edit_building_v2_context/context,
	datum/world_edit_building_v2_layout_candidate/candidate
)
	if(!istype(context) || !istype(candidate))
		return FALSE

	build_building_v2_candidate_lookups(context, candidate)

	candidate.door_plans.Cut()

	for(var/datum/world_edit_building_v2_room_connection/connection as anything in candidate.room_connections)
		if(!istype(connection))
			continue

		var/list/candidates = collect_building_v2_door_candidates(context, candidate, connection)
		if(!length(candidates))
			if(connection.required)
				candidate.errors += "door.no_candidate:[connection.id]"
			continue

		var/datum/world_edit_building_v2_opening_candidate/best = select_best_building_v2_opening_candidate(candidates)
		if(!istype(best))
			if(connection.required)
				candidate.errors += "door.no_valid_candidate:[connection.id]"
			continue

		candidate.add_door_plan(new /datum/world_edit_building_v2_route_opening_plan(
			connection.id,
			connection.kind,
			best.opening_turf,
			best.dir,
			connection.from_room_id,
			connection.to_room_id
		))

	return !length(candidate.errors)
```

## 1.7. Shared wall collection

Важно: формулировка “если у турфа стены более 2 соседей без стены — это угол” может давать ложные результаты. Надёжнее считать **shared wall segments** между двумя ownership regions.

```dm
/datum/world_edit_generator/building_layout/proc/collect_building_v2_shared_wall_segments(
	datum/world_edit_building_v2_context/context,
	datum/world_edit_building_v2_layout_candidate/candidate,
	datum/world_edit_building_v2_room_connection/connection
)
	var/list/segments = list()
	var/list/wall_candidates = list()

	var/list/from_lookup = get_building_v2_region_lookup(candidate, connection.from_room_id)
	var/list/to_lookup = get_building_v2_region_lookup(candidate, connection.to_room_id)

	for(var/turf/from_turf as anything in from_lookup)
		if(!istype(from_turf))
			continue

		for(var/check_dir as anything in GLOB.cardinals)
			var/turf/wall_turf = get_step(from_turf, check_dir)
			var/turf/to_turf = get_step(wall_turf, check_dir)

			if(!candidate.wall_lookup[wall_turf])
				continue
			if(!to_lookup[to_turf])
				continue

			wall_candidates[wall_turf] = check_dir

	return build_building_v2_wall_segments_from_turfs(wall_candidates)
```

`route` должен быть псевдо-регионом:

```dm
/proc/get_building_v2_region_lookup(candidate, region_id)
	if("[region_id]" == "route")
		return candidate.route_lookup
	var/datum/world_edit_building_v2_room_plan/R = candidate.get_room_plan(region_id)
	return R?.turf_lookup || list()
```

## 1.8. Candidate rejection

```dm
/datum/world_edit_generator/building_layout/proc/validate_building_v2_opening_candidate(
	datum/world_edit_building_v2_context/context,
	datum/world_edit_building_v2_layout_candidate/candidate,
	datum/world_edit_building_v2_opening_candidate/O
)
	if(!istype(O.opening_turf))
		O.reject_reasons += "missing_turf"
		return

	if(O.segment_len < 3)
		O.reject_reasons += "short_segment"

	if(O.corner)
		O.reject_reasons += "corner"

	if(building_v2_opening_near_existing_door(candidate, O.opening_turf, 2))
		O.reject_reasons += "near_other_door"

	var/turf/front_turf = get_step(O.opening_turf, O.dir)
	var/turf/back_turf = get_step(O.opening_turf, turn(O.dir, 180))

	if(!building_v2_opening_side_clear(candidate, front_turf))
		O.reject_reasons += "front_blocked"

	if(!building_v2_opening_side_clear(candidate, back_turf))
		O.reject_reasons += "back_blocked"
```

## 1.9. Scoring

```dm
/datum/world_edit_generator/building_layout/proc/score_building_v2_opening_candidate(
	datum/world_edit_building_v2_context/context,
	datum/world_edit_building_v2_layout_candidate/candidate,
	datum/world_edit_building_v2_opening_candidate/O
)
	var/score = 0

	score += O.segment_len * 20
	score -= O.segment_center_distance * 15

	if(O.front_clear && O.back_clear)
		score += 300

	if(O.privacy == "private")
		score -= opening_exposes_private_room(context, candidate, O) ? 400 : 0

	if(O.corner)
		score -= 10000

	if(O.near_other_door)
		score -= 1000

	return score
```

# ЭТАП 2. Scene Hierarchy: Primary / Secondary / Negative Space

## 2.1. Проблема

Сейчас scene plan часто строит один набор объектов. Например dining scene выбирает table turf и chairs offsets вокруг.  Bedroom/storage/sanitation также строятся как несколько anchors.

Это недостаточно. Комната должна иметь композицию:

```text
Primary Anchor — главный смысл комнаты.
Negative Space — проходы/пустое пространство.
Secondary Anchors — вторичная мебель.
Detail — необязательные мелочи.
```

## 2.5. Primary Anchor selection

```dm
/datum/world_edit_generator/building_layout/proc/select_building_v2_primary_anchor(
	datum/world_edit_building_v2_context/context,
	datum/world_edit_building_v2_layout_candidate/candidate,
	datum/world_edit_building_v2_room_plan/room,
	datum/world_edit_building_v2_scene_contract/scene
)
	switch(scene.primary_anchor_policy)
		if("center")
			return select_building_v2_center_anchor(context, candidate, room, scene)
		if("far_wall")
			return select_building_v2_far_wall_anchor(context, candidate, room, scene)
		if("longest_wall")
			return select_building_v2_longest_wall_anchor(context, candidate, room, scene)
		if("near_window")
			return select_building_v2_window_anchor(context, candidate, room, scene)
		if("service_wall")
			return select_building_v2_service_wall_anchor(context, candidate, room, scene)

	return select_building_v2_center_anchor(context, candidate, room, scene)
```

Rules:

```text
common/dining: center, but not on path door→door.
bedroom: far wall from door.
sanitation: wall not directly visible from door if possible.
storage: longest free wall.
workshop: service wall.
office: wall/desk facing visitor side.
```

## 2.6. Negative Space reservation

```dm
/datum/world_edit_generator/building_layout/proc/reserve_building_v2_negative_space(
	datum/world_edit_building_v2_context/context,
	datum/world_edit_building_v2_layout_candidate/candidate,
	datum/world_edit_building_v2_room_plan/room,
	datum/world_edit_building_v2_scene_plan/scene_plan
)
	var/turf/focus_turf = scene_plan.primary_anchors["focus"]
	if(!istype(focus_turf))
		return FALSE

	var/list/door_turfs = get_building_v2_room_door_turfs(candidate, room.id)
	for(var/turf/door_turf as anything in door_turfs)
		var/list/path = build_building_v2_room_internal_path(room, door_turf, focus_turf)

			scene_plan.negative_space_turfs += path_turf
			scene_plan.no_furniture_lookup[path_turf] = TRUE

	// Дополнительно: полоса вдоль основной траектории комнаты.
	reserve_building_v2_room_edge_walkway(room, scene_plan)

	return TRUE
```

## 2.7. Secondary Anchors

```dm
/datum/world_edit_generator/building_layout/proc/collect_building_v2_secondary_anchors(
	datum/world_edit_building_v2_context/context,
	datum/world_edit_building_v2_layout_candidate/candidate,
	datum/world_edit_building_v2_room_plan/room,
	datum/world_edit_building_v2_scene_plan/scene_plan
)
	var/list/anchors = list()

	for(var/turf/T as anything in room.turfs)
		if(scene_plan.no_furniture_lookup[T])
			continue
		if(candidate.route_lookup[T])
			continue
		if(candidate.door_lookup[T])
			continue
		if(context.state.fixtures.fixture_lookup[T])
			continue

		var/list/wall_dirs = get_building_v2_scene_adjacent_wall_dirs(context, candidate, room, T)

				"turf" = T,
				"wall_dirs" = wall_dirs,
				"score" = score_building_v2_secondary_anchor(context, candidate, room, T, wall_dirs)
			))

	return sort_building_v2_anchor_candidates(anchors)
```

# ЭТАП 3. Global Scene Budget

## 3.1. Проблема

Одной комнаты не хватает для принятия решений. Нужен уровень всего здания:

```text
в доме максимум 1 dining_focal;
минимум 1 sanitation;
минимум 1 bedroom;
storage должен быть хотя бы один;
optional rooms не должны вытеснять required identity.
```

---

## 3.2. Scene budget datum

```dm
/datum/world_edit_building_v2_scene_budget
	var/list/limits = list()
	var/list/minimums = list()
	var/list/used = list()

/datum/world_edit_building_v2_scene_budget/proc/can_use(scene_slot, amount = 1)
	var/current = round(text2num("[used[scene_slot]]") || 0)
	var/limit = round(text2num("[limits[scene_slot]]") || 0)
	if(limit <= 0)
		return TRUE
	return current + amount <= limit

/datum/world_edit_building_v2_scene_budget/proc/use(scene_slot, amount = 1)
	used[scene_slot] = (used[scene_slot] || 0) + amount

/datum/world_edit_building_v2_scene_budget/proc/missing_minimums()
	var/list/missing = list()
	for(var/scene_slot as anything in minimums)
		var/current = round(text2num("[used[scene_slot]]") || 0)
		var/minimum = round(text2num("[minimums[scene_slot]]") || 0)
		if(current < minimum)
			missing[scene_slot] = minimum - current
	return missing
```

## 3.6. Required rooms first

Scene solve order must be:

```text
1. required rooms with required scene kinds;
2. optional rooms with remaining budget;
3. detail/secondary scenes.
```

```dm
/proc/get_v2_scene_room_solve_order(context, candidate)
	var/list/required_rooms = list()
```

## 4.5. Ideal dimensions

```dm
/datum/world_edit_generator/building_layout/proc/building_v2_ideal_room_size(
	datum/world_edit_building_v2_room_contract/R,
	target_aspect = 1.333
)
	var/area = clamp(R.preferred_area, R.min_area, R.max_area)
	var/ideal_w = round(sqrt(area * target_aspect))
	var/ideal_h = round(max(area / max(ideal_w, 1), 1))

	ideal_w = clamp(ideal_w, R.min_width, R.max_width)
	ideal_h = clamp(ideal_h, R.min_height, R.max_height)

	return list("w" = ideal_w, "h" = ideal_h)
```

## 4.6. Rect validation

```dm
/datum/world_edit_generator/building_layout/proc/building_v2_room_rect_valid_for_contract(rect, R)
	var/w = rect["x2"] - rect["x1"] + 1
	var/h = rect["y2"] - rect["y1"] + 1
	var/area = w * h

	if(area < R.min_area || area > R.max_area)
		return FALSE

	if(w < R.min_width || h < R.min_height)
		return FALSE

	var/aspect = max(w, h) / max(min(w, h), 1)
	if(aspect > R.max_aspect)
		return FALSE

	return TRUE
```

# 8. Критерий успеха

Генерация считается улучшенной не когда JSON `passed=true`, а когда:

```text
1. комнаты имеют роли;
2. двери выбраны Opening Solver-ом из shared wall;
3. нет дверей в углах;
4. route связан и не проходит через private/service rooms;
5. каждая required room имеет primary scene;
6. common/dining не дублирует dining focal;
7. negative space не занят мебелью;
8. большие комнаты не остаются пустыми без explicit negative-space scene;
9. windows соответствуют room policy;
10. PNG визуально читается как мапперская постройка.
```

# 10. Итоговая задача для исполнителя

```text
Implement building_layout v2.1.

Goal:
Replace hardcoded living v2 room/door/scene placement with universal pattern + room allocation + opening solver + scene hierarchy.

Required changes:
1. Patterns output influence zones and room connections, not hardcoded doors.
2. Room allocator builds room rectangles from contracts using target area/aspect and rejects pen rooms.
3. Opening Solver finds shared wall segments and places doors at the best scored non-corner segment center.
4. Window Solver follows room window policy.
5. Scene Solver uses primary anchor, negative space, secondary anchors.
6. Global scene budget prevents repeated dining/social focal scenes and guarantees required bedroom/sanitation/storage scenes.
7. Quality Validator hard-fails bad visuals:
   empty large rooms,
   isolated rooms,
   invalid doors,
   thin rooms,
   scene missing,
   duplicate focal scenes,
   negative-space blocking,
   window policy violations.
8. Current bad visual outputs must fail v2 quality counters.
9. New living outputs must pass both counters and manual visual review before expanding to storage/workshop.
```

Такой план уже не про “living-костыль”. Это универсальная модель: разные программы задают свои contracts/scenes, а общий solver одинаково решает комнаты, связи, двери, окна, сцены и размещение.

## 0. Что видно по результату (строго по изображениям)

Без чтения PR-кода, только по визуализации:

### Симптомы

1. **Фурнитура/объекты размещаются как независимые точки**

   * столы/кровати/машины/контейнеры не образуют композиции
   * нет “кластеров использования” (обеденная зона, рабочая зона, склад)

2. **Нет иерархии пространства**

   * помещения не читаются как “комнаты с функцией”
   * коридоры/проходы не управляют размещением объектов

3. **Стены/двери/проёмы не формируют устойчивый каркас**

   * двери выглядят как случайные вставки, а не “узлы графа”
   * нет гарантии логики “комната → вход → доступ → мебель”

4. **Мебель не взаимодействует**

   * отсутствуют пары/группы (стол+стулья, койки+тумбы, рабочие станции)
   * объекты не “собираются в смысловые единицы”

5. **Переуплотнение / шум**

   * попытка заполнить пространство равномерно вместо функционального распределения

## 1. Диагноз (корень проблемы)

С высокой вероятностью текущая генерация — это:

> **Tile-level stochastic placement без пространственной модели**

То есть:

* каждый объект ставится **почти независимо**
* есть вероятно:

  * weighted random
  * local constraints (иногда)
* но **нет глобальной структуры (layout graph / room semantics)**

---

## 2. Что должно быть вместо (ключевой разрыв)

Сейчас:

> Tile → Object (локальная логика)

Должно быть:

> Space → Room Graph → Functional Zones → Object Clusters → Tile rendering

---

## 3. Основные архитектурные проблемы (вероятные в PR #99)

### 3.1 Отсутствие Room Semantic Layer (критично)

Нет промежуточного слоя:

* RoomType (kitchen, dorm, corridor, storage)
* Zone (work area, sleep area, transit area)
* Subzone anchors

➡️ без этого мебель всегда “слепая”

---

### 3.2 Нет “object interaction graph”

Объекты не знают друг о друге:

* стол ≠ центр группы
* стул ≠ привязан к столу
* кровать ≠ часть койко-сета

➡️ результат: случайные конфигурации

---

### 3.3 Нет constraint propagation

Примеры отсутствующих правил:

* “стул только рядом с опорной стороной стола”
* “кровать не ставится в проходной зоне”
* “дверь не должна быть внутри мебельного кластера”
* “рабочие станции требуют свободного радиуса”

---

### 3.4 Wall/door generation не как граф связности

Судя по картам:

* двери не определяют поток
* нет “main path bias”
* комнаты не имеют входной логики

---

### 3.5 Overfill strategy (ошибка плотности)

Похоже есть:

* greedy fill: “заполнить доступные клетки”

Это убивает композицию:

* пространство становится шумом
* исчезают пустоты как дизайн-инструмент

---

## 4. Рекомендуемый рефакторинг (по приоритету)

### Вариант A — **Room-first + Constraint Zones (рекомендуется)**

**~75% предпочтения**

#### Pipeline:

1. **Graph Layout**

   * генерируется граф комнат (nodes = rooms, edges = doors)

2. **Room classification**

   * спальня / склад / кухня / офис / тех. зона

3. **Zone carving внутри комнаты**

   * anchors:

     * wall-based zones
     * center zones
     * path exclusion zones

4. **Object cluster placement**

   * не объекты, а “группы”

     * table_cluster
     * bed_cluster
     * workstation_cluster

5. **Post-fill decoration (low priority)**

   * мусор / мелкие объекты / props

#### Почему это работает:

* появляется структура
* исчезает случайность на уровне смыслов
* локальный RNG остаётся, но внутри правил

---

### Вариант B — Constraint Solver (semi-global)

**~20% предпочтения**

* SAT / weighted CSP-like placement
* каждая ячейка = constraint set

Плюсы:

* точный контроль плотности
  Минусы:
* дорогой в DM/SS13 контексте
* сложно отлаживать

---

### Вариант C — Pattern library / Templates (fallback)

**~5% предпочтения**

* заранее заданные room patterns
* вставка готовых “сцен”

Плюсы:

* быстро стабилизирует качество
  Минусы:
* теряется вариативность

---

## 5. Конкретные правила, которых сейчас не хватает

### 5.1 Furniture clustering rules

* стол → требует 2–6 стульев в радиусе 1–2 tiles
* кровать → тумба/шкаф вероятностно
* workstation → монитор + консоль + свободный фронт

---

### 5.2 Spatial exclusion zones

* двери:

  * минимум 1 tile clearance
* кровати:

  * не ближе N tiles к door axis
* столы:

  * не в коридорах

---

### 5.3 Path-aware placement

* основной path (door graph shortest path):

  * должен быть **свободен от крупных объектов**
* вторичные зоны:

  * допускают плотность
